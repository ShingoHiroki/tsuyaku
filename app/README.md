# Tsuyaku の使い方

Tsuyaku は、オンライン会議の相手の発言と自分の発言を字幕にし、英⇔日に訳して表示する Mac アプリ（試作版）。実際の会議で使って、精度と遅延の感触を確かめるためのもの（完成品ではない）。

- 範囲：字幕と翻訳まで（音声の読み上げ・要約・用語辞書はまだない）
- 処理はすべてこの Mac の中で行う（クラウドに音声や文字を送らない。PLaMo のサーバーもこの Mac の中だけで動く）

> **相手の発言も字幕になる。** 使う前に相手に伝え、字幕を保存するときは相手の同意を得ること。所属先に録音・記録のルールがあれば従うこと。

## 動く環境

- Apple シリコンの Mac、macOS 26 以降
- Xcode（ビルドに使う。xcode-select が Command Line Tools を向いていても、`build-app.sh` が Xcode を使う）

## 1. ビルド

```bash
bash app/build-app.sh
```

- `app/build/Tsuyaku.app` ができる（初回は WhisperKit の取得とビルドで数分かかる）
- 作り直すたびに macOS から別のアプリとみなされ（アドホック署名）、次の「2. 初回の許可」がもう一度出ることがある

## 2. 起動と初回の許可

Finder で `app/build/Tsuyaku.app` をダブルクリックするか、次のコマンドで起動する。

```bash
open app/build/Tsuyaku.app
```

初めて「開始」を押したときに、次の許可を求められる。どちらも「許可」を押す。

| 許可 | 何に使うか | 拒否するとどうなるか |
|---|---|---|
| マイク | 自分の発言の字幕 | 「マイクの権限がありません」と出て開始できない（「マイクを使う」を外せば相手側だけで動く） |
| システムオーディオの録音 | 会議アプリから出る相手の声の字幕 | エラーは出ず、相手側の字幕が何も出ない |

拒否してしまったときは、システム設定 → プライバシーとセキュリティ から「Tsuyaku」を許可し直す（項目の名前は macOS の版で少し違うことがある）。

## 3. 翻訳エンジンの準備（初回だけ）

画面の「翻訳」で、Apple と PLaMo 0.8B・2B・8B を切り替えられる（会議の前に選ぶ。取り込み中は変えられない）。既定は PLaMo 2B なので、先に下の「PLaMo の準備」が必要。

下の表の秒数・メモリは、Apple M1・16GB で会議を想定した英文・日本文 25 文を訳したときの値（文字起こしと同時ではない単体の測定）。

| エンジン | 1文の翻訳 | メモリ | 向いている使い方 |
|---|---|---|---|
| Apple | 未測定 | ― | 言語パックだけで使える |
| PLaMo 0.8B | 約0.35秒 | 約1.2GB | 遅延を最優先するとき（言い回しの誤りがやや多い） |
| PLaMo 2B（既定） | 約0.9秒 | 約2.7GB | まずはこれ（速さと質のつり合いがよい） |
| PLaMo 8B | 約2.4秒 | 約6.3GB | 字幕には遅い。訳の質の上限を見るとき |

**Apple を使うとき**：画面の「言語パックをインストール」を押し、Apple の確認が出たら英語・日本語のダウンロードを許可する。入るまでは訳文の欄に「（翻訳の準備ができていません…）」と出る。入ったあとも表示が変わらないときは、アプリを起動し直す。

**PLaMo を使うとき**：
- 先に下の「PLaMo の準備」で Python の環境とモデルを用意する
- 選ぶと、アプリが裏で PLaMo のサーバー（この Mac の中だけで動く）を起動する（数秒）。別のエンジンに切り替えたときと、アプリを終了したときに止まる
- 直前に訳した2組を、話の流れとして PLaMo に渡している
- モデルの利用条件は [PLaMo Community License](https://plamo.preferredai.jp/info/plamo-community-license-ja) を確認する（モデルはこのリポジトリに含まれない）

### PLaMo の準備

[uv](https://docs.astral.sh/uv/)（Python の環境を作る道具）を使う。

Python の仮想環境を `.venv/` に作り（ほかの Python 環境には影響しない）、必要なパッケージを入れる。

```bash
uv venv --python 3.12 .venv
```

```bash
uv pip install --python .venv/bin/python mlx-lm mlx transformers numba huggingface_hub
```

使うサイズのモデルをダウンロードする（0.8B：0.98GB、2B：2.41GB、8B：6.07GB）。`models/plamo/` に置く（git の管理対象外）。

```bash
.venv/bin/hf download pfnet/plamo-3-translate-2b-MLX-4bit --local-dir models/plamo/plamo-3-translate-2b-MLX-4bit --exclude "figures/*"
```

- 0.8B・8B を使うときは、コマンドの `2b` を `0.8b`・`8b` に変える
- モデルには Python のコードが同梱されており、読み込むときに実行される（`trust_remote_code`）。モデルを更新したときは、同梱のコードの中身を確認する

## 4. 会議での使い方

1. **ヘッドホンを使う**。スピーカーだと相手の声がマイクにも入り、自分側に誤った字幕が出る。画面の「出力」で、イヤホンなどに切り替えられる（スピーカーから音が出ていると警告が出る）
2. 会議に参加し、相手の声が聞こえる状態にする（音が出ていないと会議アプリを見つけられない）
3. 画面の設定を選ぶ

   | 項目 | 選び方 |
   |---|---|
   | 会議アプリ | 使っている会議アプリ。Zoom・Teams で「見つかりません」と出たら「システム全体」を選ぶ（Zoom・Teams の判定は未確認） |
   | 相手の認識 | Apple＝速い。WhisperKit＝英語の精度が高いが、区切りごとにまとめて処理するので字幕が出るまで遅い |
   | 相手の言語 | 相手が話す言語。英語なら地域も選ぶ（地域は Apple のときだけ効く。インド英語なら「英語（インド）」）。**日本語**を選ぶと、相手の発言を英語に訳す |
   | 翻訳 | 上の「3. 翻訳エンジンの準備」を参照 |
   | 自分の認識 | 既定は WhisperKit（日本語と英語が混ざっても書き出せる）。遅いと感じたら Apple（日本語として聞き取るので、英語の発言はうまく書き出せない） |
   | マイクを使う | 自分の発言も字幕にするならオン |
   | マイク | 使うマイク。既定は「システムの設定に従う」。選んだ装置は次に起動したときも使う（抜かれていたら、システムの設定のマイクを使う） |
   | 出力 | 会議の音を聞く装置（イヤホンなど）。**切り替えると Mac 全体の出力が変わる**（ほかのアプリの音も同じ装置から出る）。会議アプリの中でスピーカーを選んでいる場合は、そちらが優先される。取り込み中でも切り替えられ、切り替えると相手側の取り込みを自動で始め直す |
   | 記録 | 下の「5. 字幕の保存」を参照。既定は保存しない |

4. **「開始」**（⌘Return）を押す。WhisperKit を選んだときは、初回と、アプリを作り直した後の最初の1回に、「準備中…」が数分続くことがある（macOS がモデルをニューラルエンジン用に変換するため。Apple M1・16GB での実測では初回約12分、作り直した後は約4分のときと2秒のときがあった。普段は数秒）。会議の前に一度「開始」→「停止」しておくとよい
5. 終わったら **「停止」** を押す

### 画面の見方

- 左のラベル：「相手」（会議アプリの音）／「自分」（マイク）
- 灰色の文：聞き取り中（まだ変わる）。黒くなったら確定
- 大きい文字：訳文。英語の発言は日本語に、日本語の発言は英語に訳す（言語は書き出された文から自動で判定）
- 小さい文字：使ったエンジン、話し終わってから確定・訳文が出るまでの秒数
- 上の「遅延」：話し終わりから訳文までの秒数の中央値と、遅い方から1割の値（目標は1〜3秒）
- 「WhisperKit の調整…」：別のウィンドウで、話し始めの判断（基準の下限・上限・雑音の倍率）、雑音の区切りを捨てる秒数、捨てる相づち・決まり文句の一覧、Whisper の自信の基準を変えられる。「保存」（⌘S）すると、取り込み中でも次の音・次の区切りからすぐ反映される。保存した値は次に起動したときも使う。「既定に戻す」で元の値に戻せる（保存するまで反映されない）
- 「相手の音」「自分の声」のバー：取り込んでいる音の大きさ。話している（音が出ている）と判断している間は、ランプとバーが緑に光る。オレンジの縦線は、WhisperKit が話し始めと判断する音量（マイクの雑音に合わせて自動で変わる）。しゃべってもバーが動かないなら、音が届いていない

## 5. 字幕の保存

- 「字幕を保存する（文字だけ）」をオンにし、**相手に字幕を保存することを伝えてから**「相手に伝えた」をオンにする。両方オンのときだけ保存される
- 停止したときに、会議1回分が Markdown と JSON で保存される。音声は保存しない
- 保存先：`~/Library/Application Support/Tsuyaku/records/`（「保存先を Finder で開く」で開ける）。消すときは Finder で削除する
- 同じフォルダーの `metrics.csv` には、保存の設定に関係なく、発言ごとの遅延の秒数と文字数だけが追記される（発言の中身は書かない）。遅延の集計に使える
- 同じフォルダーの `trace.log` には、準備・許可・取り込みの開始と停止などの段階と時刻、音声の形式（周波数・チャンネル数）が書かれる。取り込み中は30秒ごとに、相手側・自分側それぞれの届いた音の秒数・最大の音量・確定した件数・捨てた件数・話し始めの基準も書く（発言の中身や、発言ごとの秒数・文字数は書かない。装置の名前も書かず、種類だけ書く）。止まったときに、どの段階で止まったか、音が届いていないのか届いているのに捨てられているのかを調べるためのもの。アプリを起動するたびに書き直される

## 6. うまくいかないとき

| 症状 | 確かめること |
|---|---|
| 「〇〇 の音声のプロセスが見つかりません」 | 会議に参加して相手の声が出ているか。Zoom・Teams なら「システム全体」に切り替える |
| 相手側の字幕が出ない | システムオーディオの録音の許可（2. を参照）。作り直した直後は許可し直しが必要なことがある |
| 「開始」から字幕が始まるまで・「停止」から止まるまでに、それぞれ約90秒かかる | システムオーディオの録音の許可の確認（ダイアログ）に答えていない。macOS は答えを最大90秒待ち、答えがないと音声なしのまま進む（相手側の字幕が出ない）。ダイアログはほかのウィンドウの後ろに隠れていることがあるので、探して「許可」を押す（待っている間は、画面の状態の欄にも案内が出る）。アプリを作り直した直後や初めて使うときに出る。どの段階で止まったかは `trace.log`（5. を参照）で分かる |
| 自分の声が拾われたり拾われなかったりする | 「自分の声」のバーを見る。動かないならマイクの音が届いていない（イヤホンのミュート、「マイク」の選択を確認）。動くのに緑に光らないなら、声がオレンジの線より小さい。マイクを口に近づける。Bluetooth のイヤホンは会議中に通話用のモードになり、声が小さく届きやすい（実測で最大 0.007〜0.011） |
| 自分側に変な字幕が出る | ヘッドホンを使っているか（画面の「出力」を確認） |
| 「スピーカーから音が出ています」と出る | 内蔵スピーカー・画面のスピーカーなどから音が出ている。「出力」でイヤホンなどに切り替える。Bluetooth・USB の装置は、イヤホンかスピーカーか判別できないため警告しない |
| 訳文が出ない | Apple なら言語パック、PLaMo なら Python の環境とモデル（3. を参照）。PLaMo のサーバーのログは保存先フォルダーの `plamo-server.log` |
| 「準備中…」のまま進まない | WhisperKit の初回と作り直した後は数分〜十数分かかることがある（アクティビティモニタで `ANECompilerService` が動いていれば変換中）。それが動いていないのに15分以上続くときは、アプリを終了して起動し直す |
| 「はい」「ありがとう」などの短い字幕が勝手に出る | WhisperKit が小さな雑音から文を作ってしまう現象（ハルシネーション）。声のある時間が0.3秒未満の区切りは文字起こしせず、自信の低い文と、3秒未満の区切りで決まった相づちだけの文は捨てているが、すべては防げない。ヘッドホンを使うと減る。「WhisperKit の調整…」で、捨てる相づちを足したり、声の最短の秒数を長くしたりできる |
| 「はい」「ありがとう」「ありがとうございます」「Thank you」などとだけ言っても字幕が出ない | 上のハルシネーション対策で捨てているため（3秒未満の区切りでこの言葉だけのとき）。相づちは訳さなくても話の筋は追えるため、誤った字幕を減らす方を選んでいる。出したい言葉は「WhisperKit の調整…」の一覧から消す |
| 相手と自分が同時に話すと字幕が遅れる | WhisperKit を両方で使うと、モデル1つを順番に使うため、もう一方の処理を待つ（1件あたり1秒前後）。字幕が出なくなるわけではない |
| WhisperKit で、相手が続けて話すと字幕がなかなか出ない | 区切り（4秒を超えたら0.3秒の息継ぎ、それより短ければ0.7秒の無音。どちらもなければ12秒で一番静かな所）が来るまで、まとめて待つため |
| Chrome の別のタブの音（動画など）まで字幕になる | Chrome の音はまとめて取り込むため。会議中は他のタブで音を出さない |

## 開発者向け：自動テスト

画面を操作せずに、システム全体の音を指定秒数だけ処理して結果をファイルに書き、終了する。

```bash
mkdir -p app/build/logs
```

```bash
open -W -n app/build/Tsuyaku.app --args --autotest 60 "$PWD/app/build/logs/autotest.txt" Apple Apple
```

- 引数：`--autotest <秒> <結果ファイル> [<相手のエンジン> <自分のエンジン> [<翻訳エンジン>]]`（文字起こしは `Apple` か `WhisperKit`、翻訳は `apple`・`plamo-0.8b`・`plamo-2b`・`plamo-8b`）
- 起動したら、別のターミナルで英語や日本語の音声ファイルを流す（例：`afplay <音声ファイル>`）
- 進み具合は `<結果ファイル>.trace` に書かれる（普段の `trace.log` の段階に加えて、WhisperKit の発言ごとの秒数・文字数も書く）。予定より10分以上長引くと、止まった段階を結果ファイルに書いて終了する（WhisperKit の初回のモデルの変換待ちを見込んでいる）

## ファイル

| ファイル | 内容 |
|---|---|
| `app/Sources/Tsuyaku/App.swift` | 画面 |
| `app/Sources/Tsuyaku/SessionModel.swift` | 開始・停止、字幕と翻訳の受け渡し、自動テスト |
| `app/Sources/Tsuyaku/AudioSources.swift` | 会議アプリの音（Core Audio Process Tap）とマイクの取り込み |
| `app/Sources/Tsuyaku/Transcribers.swift` | 文字起こし（Apple・WhisperKit）と、文の言語の判定 |
| `app/Sources/Tsuyaku/WhisperTuning.swift` | WhisperKit の調整の値（保存とすぐの反映）と、調整の画面 |
| `app/Sources/Tsuyaku/Services.swift` | 翻訳（Apple・PLaMo のサーバーの起動と問い合わせ）、保存、遅延の記録、自動テストの進み具合の記録 |
| `app/Info.plist` | アプリ名、アイコンのファイル名、許可を求めるときの説明文、この Mac の中のサーバーとの http 通信の許可 |
| `app/build-app.sh` | ビルドして .app にまとめ、アイコンを入れて署名する |
| `app/Icon/AppIcon.svg` | アイコンの元の絵（T の形＝一番上の字幕の行と一番高い音の波） |
| `app/Icon/make-icon.sh`・`app/Icon/render.swift` | 元の絵からアイコン（`app/Icon/AppIcon.icns`）を作り直す。絵を直したら `bash app/Icon/make-icon.sh` を実行してから、`bash app/build-app.sh` でビルドする |
| `app/Icon/AppIcon.icns` | アプリのアイコン（16〜1024 ピクセルの10種類をまとめたもの） |

WhisperKit のモデルは `models/` に置く。ない場合は初回に自動でダウンロードする（約 600MB）。
